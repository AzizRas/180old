# Настройка cron — по шагам

## Что это и зачем

Cron — это будильник на хостинге. Он раз в 10 минут открывает один файл
вашего сайта, и тот делает фоновую работу.

Без cron приложение работает, но **не будет**:

* персональных заданий на новую неделю (ИИ их генерирует именно там);
* сообщений коуча, которые он пишет первым;
* напоминаний о встречах группы за 2 часа;
* автоматического создания встреч на следующую неделю;
* закрытия экспедиций и уборки мусора в базе.

То есть без cron у вас останется примерно половина продукта. Настроить —
две минуты, делается один раз.

---

## Шаг 1. Придумайте ключ

Откройте `config.php`, найдите строку:

```php
'cron_key'      => 'CHANGE_ME_CRON_KEY',
```

Замените на любой набор букв и цифр без пробелов, например:

```php
'cron_key'      => 'k7fj28dhs91qmx4',
```

Это пароль, чтобы посторонний не мог запускать вашу фоновую задачу.
Запишите его — понадобится на шаге 3.

Сохраните файл и залейте на хостинг.

---

## Шаг 2. Проверьте, что работает

Откройте в браузере (подставьте свой ключ):

```
https://180kun.online/cron.php?key=k7fj28dhs91qmx4
```

Должен появиться простой текст вроде:

```
proactive: 0
week_plans: 0
meeting_reminders: 0
expeditions_closed: 0
ok 1s
```

Нули — это нормально, пока нет пользователей. Главное, что нет ошибки
и нет слова `forbidden`.

Если написано `forbidden` — ключ в адресе не совпал с ключом в `config.php`.

---

## Шаг 3. Добавьте задание в cPanel

1. Зайдите в панель Namecheap → **cPanel**.
2. Найдите раздел **Advanced** → **Cron Jobs**.
3. В блоке **Add New Cron Job**:
   * **Common Settings** — выберите `Twice per hour (0,30 * * * *)`,
     а затем в поле **Minute** впишите вручную: `*/10`
     (остальные поля: Hour `*`, Day `*`, Month `*`, Weekday `*`).
   * **Command** — вставьте одной строкой:

```
curl -s "https://180kun.online/cron.php?key=k7fj28dhs91qmx4" > /dev/null 2>&1
```

4. Нажмите **Add New Cron Job**.

Готово. Внизу страницы появится ваше задание в списке.

---

## Если curl на хостинге недоступен

Иногда shared-хостинг не даёт `curl` в cron. Тогда используйте команду
с прямым запуском PHP:

```
/usr/local/bin/php /home/ВАШ_ЮЗЕР/public_html/cron.php > /dev/null 2>&1
```

Где `ВАШ_ЮЗЕР` — имя пользователя cPanel (видно в левом верхнем углу панели),
а `public_html` — папка, куда вы залили сайт. При таком запуске ключ не нужен:
из командной строки файл запускается без проверки.

Точный путь к PHP cPanel обычно подсказывает сама — в разделе Cron Jobs
внизу есть строка с примером.

---

## Шаг 4. Убедитесь, что задание реально срабатывает

Через 15 минут после добавления зайдите в админку → вкладка
**Инструменты**. Там в строке `cron` будет ваша ссылка, а рядом с
метриками начнут появляться цифры.

Ещё проще: cPanel умеет присылать вывод cron на почту. В поле
**Cron Email** вверху страницы Cron Jobs впишите свой email — и первые
пару дней будете видеть, что задание отрабатывает. Потом уберите,
чтобы не засорять почту.

## Как часто запускать

**Каждые 10 минут** — это оптимум:

* сообщения коуча приходят людям в течение дня равномерно, а не пачкой;
* нагрузка размазана: за один запуск обрабатывается до 25 человек для
  коуча и до 12 недельных пакетов заданий;
* напоминания о встречах приходят вовремя.

Реже (раз в час) — тоже рабочий вариант, но напоминания о встречах
станут менее точными.

Чаще 5 минут не нужно: ничего не ускорится, только лишние запуски.

## Частые вопросы

**Cron нагрузит хостинг?**
Нет. Один запуск — это один PHP-процесс на несколько секунд. Он ограничен
по времени изнутри (110 секунд максимум) и не запускается второй раз, если
предыдущий ещё работает — стоит блокировка.

**Что если два запуска наложатся?**
Второй сразу выйдет со словом `busy`. Это предусмотрено.

**Можно вызывать cron.php вручную?**
Да, просто откройте ссылку в браузере. Это безопасно и ничего не сломает.

**Я вижу `busy` каждый раз**
Значит, остался файл блокировки от аварийно завершившегося запуска.
Удалите `data/cron.lock` через файловый менеджер — и всё заработает.
